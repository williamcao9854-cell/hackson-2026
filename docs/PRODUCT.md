# 「说得出」SayIt：个性化图片沟通板

> 赛道一：Apple Human-Centered Care
> 技术栈：Swift · SwiftUI · Core ML · AMD 图像生成 API

---

## 一、要解决的问题

### 谁需要它？

- **自闭症、语言发育迟缓的儿童**：能理解，但说不出或说不清
- **中风后失语的老人**：脑子清楚，话到嘴边说不出来
- **渐冻症、脑瘫患者**：发声和运动都受限

这些人在康复中普遍使用 **AAC（辅助沟通）**，最常见的形式是图片沟通板：指一指图卡，就能表达意思。

### 现有方案的痛点

| 痛点 | 具体表现 |
|---|---|
| 图卡太通用 | 只有"食物""玩具"，没有"奶奶煮的粥""我的蓝色小熊" |
| 自己做卡太累 | 家长拍照、打印、过塑，一张卡要十几分钟，照片背景杂乱，孩子认不出 |
| 风格不统一 | 照片、网图、手绘混在一起，认知负担大 |
| 专业软件贵 | Proloquo2Go 这类软件要 1000 多元，而且多数是英文 |

### 核心洞察

AAC 领域把词汇分成两类：

- **核心词**（我、要、不要、还要、停、帮我……）：大约 50 个词覆盖日常 80% 的表达，**人人通用**
- **边缘词**（具体的人、物、地点）：**每个人都不一样**，正是现有产品做不好的部分

👉 **我们的定位：核心词用预置图卡，边缘词用 AI 按需生成。** AI 只用在真正需要个性化的地方。

## 二、两个角色、两种界面

### 👩 照顾者端（家长、护工、康复师）：负责"造卡"

1. **文字造卡**：输入"奶奶的粥"，选好分类，点生成，调用 AMD 图像生成 API，得到一张统一风格的图卡
2. **拍照造卡**（Core ML）：用相机对准家里的杯子，设备端模型识别出"杯子"，自动填好名称，确认后生成图卡
3. **管理图卡**：不满意可以重新生成，可以编辑名称和分类、删除、调整顺序
4. **使用记录**：看到孩子最常表达什么，比如"今天说了 5 次'疼'"

### 🧒 使用者端：负责"说话"

1. 屏幕上是**大图卡网格**，按颜色分类
2. 点一张卡，它就出现在顶部的**句子条**，同时读出这个词
3. 点几张拼成一句："我 + 想要 + 奶奶的粥"
4. 点句子条上的 🔊，整句读出来
5. **完全离线、零等待**：图卡都已经生成好存在本地，不会因为网络卡住

两端切换需要长按 3 秒，或者输入密码，防止孩子误删卡片。

## 三、设计思维

| 设计决策 | 原因 |
|---|---|
| **AI 生成放在照顾者端，使用者端只读缓存** | 生成要好几秒，还依赖网络；使用者要的是即时和稳定。表达被打断，对失语者是很大的挫败 |
| **固定的提示词模板** | 保证每张卡风格一致（扁平、粗线、白底、居中、无文字），降低认知负担 |
| **Fitzgerald 颜色编码** | AAC 行业标准：人物用黄色、动作用绿色、描述用蓝色、物品用橙色、社交用粉色。康复师一眼就熟悉 |
| **卡片位置固定** | AAC 用户靠肌肉记忆找卡，位置乱动等于重新学习 |
| **大点击区域、没有时间限制** | 照顾到运动功能受限的用户 |
| **成人模式** | 给中风老人用时换成写实风格，避免幼稚化，**保护使用者的尊严** |
| **支持 Apple 无障碍功能** | VoiceOver、动态字体、切换控制（Switch Control），重度运动障碍的用户也能用 |

## 四、技术方案

```
┌──────────────── SwiftUI App ────────────────┐
│  使用者端 BoardView      照顾者端 CaregiverView │
│  ├ 句子条 SentenceBar    ├ 文字造卡            │
│  ├ 图卡网格 CardGrid     ├ 拍照造卡 ──► Core ML │
│  └ 语音 AVSpeechSynth    └ 卡片管理            │
│               │                  │           │
│        CardStore（本地存储：SwiftData + 图片文件）│
│                                  │           │
│                    ImageGenService ──► AMD API │
└──────────────────────────────────────────────┘
```

- **界面**：SwiftUI
- **语音**：`AVSpeechSynthesizer`，系统自带，支持中文，离线可用
- **Core ML**：Apple 官方 **MobileNetV2** 模型，通过 `VNCoreMLRequest` 做物体识别。模型输出英文标签，用常见物品中英对照表转成中文，识别不准时照顾者可手动修改
- **存储**：SwiftData 存卡片信息，图片存为 PNG 文件
- **AMD API**：封装成 `ImageGenService`，Key 放在不提交到仓库的配置文件里

### 提示词模板（初稿）

```
A simple flat pictogram of {物品}, thick black outline, soft pastel colors,
plain white background, centered, no text, AAC communication symbol style
```

中文名可能需要先翻译成英文再生成，取决于 AMD 那边的模型。备选：iOS 18 自带离线翻译（Translation 框架）。

### 数据模型

```swift
Card {
  id
  label        // "奶奶的粥"
  category     // 人物 / 动作 / 描述 / 物品 / 社交
  imagePath
  isCore       // 是否预置核心词
  position     // 网格中的固定位置
  useCount     // 使用次数
}
```

## 七、3 分钟路演脚本（初稿）

1. **（30 秒）讲故事**：小宇 6 岁，有自闭症，他想要奶奶煮的粥，但沟通板上只有"食物"……
2. **（30 秒）讲痛点 + 洞察**：核心词通用，边缘词个性化，现有产品做不好后者
3. **（90 秒）现场演示**：妈妈输入"奶奶的粥"生成图卡；拿起杯子拍照，识别出来自动建卡；切到孩子端，点"我 + 想要 + 奶奶的粥"，手机读出这句话
4. **（30 秒）讲设计思维**：为什么生成放在照顾者端、为什么统一风格、为什么离线优先
