## 方案 A ⭐ 「改个结局」：帮孩子把噩梦画成好梦

### 一句话
孩子说出昨晚的噩梦，然后**自己决定新的结局**。App 只把"新结局"画成绘本，睡前和爸妈一起看。噩梦一次都不画。

### 故事
5 岁的朵朵连续一周梦到"黑影怪"追她，每晚哭醒，不敢关灯。妈妈打开 App，朵朵讲完梦，App 问她："如果你有超能力，你想让黑影怪变成什么？"朵朵说："变成一只怕痒的大棉花糖！"几秒钟后，屏幕上出现一页绘本：一只软乎乎的棉花糖怪被朵朵挠得哈哈大笑。之后每晚睡前，她都要再看一遍。

### 背后的真实方法（这是方案的底气）
- 心理学里有一种治噩梦的方法叫**意象排练疗法（IRT，Imagery Rehearsal Therapy）**：把噩梦写下来，**改写成一个新结局**，每天在脑子里排练新版本。美国睡眠医学会（AASM）把它列为噩梦障碍的推荐疗法。
- IRT 最难的一步是**"在脑子里清楚地想象新结局"**。成年人都很难做到，5 岁孩子更难。
- 👉 **我们的洞察：图像生成正好补上这一步。** 孩子负责想象，AI 负责把想象变成看得见的画面，排练从"脑补"变成"看绘本"。
- 儿童噩梦很常见，AASM 的数据是 3–6 岁儿童中有 10%–50% 的噩梦严重到会打扰父母（路演前再核实一下来源）。

### 魔法时刻
孩子说出"变成棉花糖"，**几秒钟后，这个画面就出现在眼前**。孩子会第一次觉得：我能控制我的梦。

### 核心流程
1. **讲梦**（语音或家长代打字）：系统只记录，**不生成图片**
2. **找出"坏东西"**：App 提炼出梦里吓人的元素（黑影怪、掉下去、迷路）
3. **改结局**：用孩子听得懂的引导卡片提问："它其实怕什么？""你有什么超能力？""谁来帮你？"孩子选卡片或者自己说
4. **生成绘本**：调用 AMD API，把新结局画成 2–4 页统一画风的绘本
5. **睡前排练**：每晚睡前，App 自动播放这本绘本，配温柔的语音朗读
6. **恐惧温度计**：每天早上孩子拖动一个表情滑块，"昨晚害怕吗？"家长可以看到一周的变化

### Core ML 的作用
- **语音转文字**：Apple Speech 框架，设备端运行，孩子的梦不上传
- **恐惧元素提取 + 情绪打分**：用 Create ML 训练一个设备端文本分类器（Core ML 模型），识别梦里的恐惧类型（被追、坠落、黑暗、分离……），并给出害怕程度。App 据此选择合适的引导问题
- **隐私是加分点**：孩子的梦是非常私密的内容，识别和分析全部在设备上完成，只有"新结局"的描述会发给图像 API

### 设计思维亮点
| 设计决策 | 原因 |
|---|---|
| **永远不生成噩梦本身** | 把噩梦画出来，等于强化它。这条原则写死在代码里 |
| **结局由孩子决定，不由 AI 决定** | IRT 起作用的关键是"掌控感"，AI 只是画笔 |
| **引导卡片代替开放式提问** | 5 岁孩子面对"你想怎么改？"会卡住，有选项才能说出来 |
| **画风固定：柔和、圆润、暖色** | 生成的提示词模板里带安全约束，不会画出吓人的东西 |
| **家长先看，再给孩子看** | 生成结果先过家长这一关 |
| **定位是睡前陪伴工具，不是医疗产品** | 不夸大疗效；噩梦持续严重时，App 会提示家长去看医生 |

### 4 人分工
- A：讲梦 + 改结局的对话流程（SwiftUI）
- B：绘本阅读器 + 睡前播放模式 + 恐惧温度计
- C：Core ML，包括语音识别、恐惧分类器训练（Create ML）
- D：AMD API 接入、画风提示词调优、海报、路演

### 风险
- AI 可能画出吓人的图：提示词加安全约束 + 家长预览，双重保险
- 评委质疑医疗效果：强调"基于 IRT 思路的陪伴工具"，不说"治疗"

## 方案 B 「讲给你听」：把爷爷奶奶的一生，变成孙辈愿意看的绘本

### 一句话
老人对着手机讲往事，App 实时把它画成一页页绘本。画错了，老人会忍不住纠正，**于是讲得更多**。

### 故事
王爷爷 78 岁，独居。孙子在外地上大学，每周打一次电话，聊三分钟就没话了。王爷爷讲："我 16 岁那年，光着脚在稻田里追一头跑掉的水牛……"屏幕上出现一页画。王爷爷看了直摇头："不对不对，那时候的房子是土墙，不是砖房！"改完重新生成，他越讲越起劲。周末，孙子收到一本《爷爷的 1962》。

### 洞察
- 老人的故事很宝贵，但**"写回忆录"门槛太高**，打电话又是一次性的，转眼就没了
- 年轻人不爱听长篇往事，但**会看、会转发一本绘本**
- 🔑 **最有意思的发现：画错了反而是好事。** "不对，是土墙"会引出更多细节。生成图像在这里不只是输出结果，而是**引出记忆的提问者**。心理学上本来就有"怀旧疗法"，用旧照片引导老人回忆
- 中国 60 岁以上人口约 3 亿，空巢老人的孤独感是真实存在的社会问题

### 魔法时刻
老人说"不对，是土墙"，画面就重新生成，房子变成了土墙。**他的记忆被看见了。**

### Core ML 的作用
- Apple Speech 设备端语音识别（普通话、粤语）
- NaturalLanguage + Core ML 提取故事里的**人物、地点、年代、物品**，自动拼成生成提示词，并带上年代画风（"1960 年代中国南方农村"）
- 纠正识别：识别出"不对，是……"这类句式，只替换对应的元素重新生成

### 设计思维亮点
- 画风明确是"绘本插画"，**不伪装成老照片**，不制造假记忆
- 大字、大按钮、全程语音，零打字
- 每一页都由老人确认后才保存，他是作者

### 风险
- 方言识别差：家人可以代为输入，或者先只支持普通话和粤语
- 魔法时刻依赖实时生成速度，要看 AMD API 有多快

## 方案 C 「疼痛画像」：让看不见的疼，被医生看见

### 一句话
疼痛说不清楚？在人体图上点出位置，选几个比喻（"像被针扎""像被石头压着"），App 生成一张**疼痛画像**，拿给医生看。

### 洞察
- 疼痛是最常见的就医原因，却**完全靠嘴描述**："哪种疼？""疼几分？"
- 最难描述清楚的人恰恰最需要帮助：孩子、老人、说方言或外语的人、自闭症患者
- 医学上有 **McGill 疼痛问卷**，用"灼烧、刺痛、绞痛、压迫"这类词描述疼痛。我们把这些词**变成画面**
- 艺术治疗里本来就有"疼痛画像"这种做法，慢性疼痛患者画出自己的疼

### Core ML 的作用
- PencilKit 手绘疼痛区域，根据压感和涂抹面积估计强度
- 设备端文本分类器，把患者的自由描述对应到 McGill 分类（感觉、情感、评价）

### 风险
- 医生到底要图片还是结构化数据？可能还是一张"疼痛摘要卡"更实用，图像生成的必要性比 A、B 弱
- 医疗场景容易被追问准确性

## 推荐：方案 A「改个结局」

1. **只有它，图像生成是"疗法本身"**：IRT 缺的正是可视化，我们补上了。这句话就能撑起整个路演
2. **"永远不画噩梦"**这条原则，是评委很喜欢的那种**克制的设计思维**
3. 演示时孩子说出天马行空的结局（"变成会跳舞的棉花糖"），AI 当场画出来，**有趣，也让人有共鸣**
4. 海报也很好做：一张"黑影怪变成棉花糖"的前后对比
